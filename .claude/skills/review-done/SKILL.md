# 완료 결과 검토

## 원칙

- 최종 통제력은 사람에게 있다. 사용자가 AI 작업 결과물을 최대한 직접 확인하고 검토할 수 있게 돕는 것이 이 검토의 목적이다.
  Claude가 확인한 것도 사용자가 직접 확인할 수 있는 방법을 함께 알린다.
- 통과 여부는 사용자가 정한다. Claude는 검토 결과와 의견을 제시할 뿐 스스로 통과시키지 않는다.
- 검토는 작업을 수행한 세션과 다른 세션에서 한다. 작업한 맥락에 끌려가지 않고 산출물만 보고 판단하기 위해서다.
  지금 대화에서 그 작업을 직접 했다면, 그 사실을 알리고 새 세션에서 검토하기를 제안한다.

## 1. 무엇이 수행되었는지 파악

- 프로젝트를 살펴 계획에서 어떤 단계가 수행되었는지, 그 단계의 목표와 완료 기준이 무엇인지 파악한다.
- 작업 이력과 산출물로 실제로 무엇이 만들어지고 바뀌었는지 확인한다. 계획 문서의 기록보다 실제 산출물을 기준으로 본다.

## 2. 검토

- **Claude가 확인할 수 있는 것:** 직접 확인한다. 완료 기준 충족 여부, 실행·테스트 결과, 산출물 사이의 일관성, 누락, 계획과 다르게 된 부분 등을 본다.
  문제가 있으면 무엇이 문제인지, 근거(파일·위치·실행 결과)와 함께 알린다. 문제가 없던 항목도 무엇을 어떻게 확인했는지 짧게 적는다.
- **사용자가 직접 확인해야 하는 것:** 무엇을 어떻게 보면 되는지 알려준다.
  열어 볼 파일이나 화면, 실행할 명령, 무엇을 기준으로 판단하면 되는지를 구체적으로 적는다.
  사람의 판단이 필요한 것(품질, 의도와 맞는지, 취향)과 Claude가 확인했지만 사람이 다시 봐야 할 만큼 중요한 것을 우선한다.
- **상위 문서:** 이번 결과 때문에 상위 문서(계획, 개요, 기준 등)를 수정해야 할 부분이 있는지 판단한다.
  있으면 어느 문서의 어느 부분을 어떻게 고칠지 제안한다. 사용자 확인 전에는 고치지 않는다.

## 3. 통과 후

- 사용자가 통과시키면 진행 계획/상황 문서를 업데이트한다(완료 표시, 날짜, 산출물 위치, 검토 중 정해진 내용 등). 승인된 상위 문서 수정도 반영한다.
- 프로젝트의 작업 규칙(브랜치, 커밋, 기록 방식 등)을 따른다.
